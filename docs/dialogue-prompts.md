# NPC 대화 프롬프트 변경과 검증

대화의 자연스러움은 문장 길이·반말·거절 횟수로 판정하지 않는다. **상대의 말에 맞게 반응하고, 관계에 맞는 말투를 유지하며, 답을 기다릴 자리를 남기는지** 원문으로 비교한다. 긴 설명을 청한 상황에는 충분히 설명해야 하고, 친절한 인물이 무조건 까칠해지거나 질문에 침묵하는 것은 개선이 아니다.

## 2026-11-08 · 이견의 기억과 상황 투입

장터 대조군에서 한 사람은 자신이 양보했을 때의 손해를 설명한 문장 끝에서 바로 양보했다. 당시 엔진은 같은 소재가 반복되면 여러 사람의 대화를 ‘이미 서로 넘긴 대목’이라고 표시했다. 과수원에서는 예정 사건에 적힌 최종안 작성 지시까지 가상의 화자 ‘상황’의 발언으로 전달했다. [Luna 원문과 판독](reviews/scene-agency-2026-11-08/report.md)

| 버전 | 변경 이유와 적용 내용 |
|---|---|
| `npc-lab/13` · `scene-observation/1` | 상황의 출처를 사람의 권위로 오해할 여지를 줄였다. NPC가 받는 사건에는 관찰 본문과 순번이 담긴다. 수신 처리, 차례 시작, 개인 기억 모두 같은 관찰을 사용한다. 실제 현장 인물의 말은 관찰 안에 화자와 함께 남는다. |
| `topic-closure/1` | 같은 단어의 반복으로 동의를 추정하던 경로를 고쳤다. 인물별 최근 입장과 본인이 내려놓은 화제의 출처를 보존한다. |
| `topic-closure/2` | 상대가 방금 거부하거나 자신의 차례를 주장했을 때 본인의 관련된 앞선 말이나 이해관계를 함께 떠올린다. 이견이 생기지 않은 대화에는 그 근거를 덧붙이지 않는다. |
| `topic-closure/3` | 여러 입력 항목이 같은 원문을 인용해 두 사람이 긴 변론을 되풀이했다. 한 번 전달된 원문은 출처 순번으로 참조하고 반응의 길이·행동·침묵을 인물에게 맡겼다. 장터의 두 실행은 이견이 남았지만, 기존 카페에서는 대사 128차례를 모두 소진했다. |
| `topic-closure/4` | 카페에서 본인이 여러 번 내려놓았던 소재도 계속 최근 입장으로 떠올랐다. 본인이 실제로 선택한 출처가 최근 18개 발언 안에 있는 동안 회상을 줄였다. 오래된 출처가 창 밖으로 밀린 카페에서는 여전히 128차례를 소진했다. |
| `topic-closure/5` | 오래된 출처도 본인이 고른 말과 최근 발언에 공통되는 단어 둘 이상이 있는지 확인한다. 새 질문·거절·현장 변화가 없고 같은 화제만 다시 들었다면 현재 수신 내용과 들을 사람만 떠올릴 수 있게 회상을 줄인다. 선택과 침묵은 여전히 해당 NPC가 정한다. 명시적 이견이 없는 반복에서도 각 사람의 마지막 말은 남긴다. 새 실행의 기본값이다. |
| `experiment-authoring/3` | 작성 도구가 사건의 관찰 내용과 운영 메모를 나누도록 JSON 지침을 갱신했다. 기본팩 6개 세계의 예정 사건 18개에 관찰을 작성했다. |

대화 연기 지침은 `npc-dialogue/5`다. 두 엔진 버전은 실행 생성 시 고정한다. 기존 실행은 저장된 입력 정책으로 재개한다.

## 2026-11-08 · 끝난 화제와 짧은 인물 설정

|---|---|
| `conversation-memory/1` | 카페에서는 레몬 농담을 다른 사람이 조금씩 바꿔 말했고, 관측기지에서는 점검 결론이 다음 차례의 소재가 됐다. 인물이 본 대화에서 같은 소재가 여러 사람 사이에 반복되면 오래된 중복 인용을 줄인다. 각자의 네 번째 선택마다 기존 NPC 호출 안에서 이미 놓아도 될 원문 한 건 또는 `null`을 고른다. 승인된 선택과 함께 출처 순번을 개인별로 최대 네 개 저장하고, 관련 화제가 돌아오면 실제 화자·원문을 다시 보여 준다. |
| `conversation-memory/2` | /1에서는 잠시 모두 조용해져도 마지막 유의미한 대화가 다음 호출에 다시 들어갔다. 본인이 쉬기로 했고 새 관찰이나 진행할 행동도 없는 차례는 그 휴식 상태에서 시작한다. 실제 현장에서는 본인 목표와 관련된 최근 행동과 자신이 관찰한 세계 판정을 한 쌍으로 불러온다. 새 발언·사건·질문과 처리할 이동이나 행동은 계속 전달한다. 세계가 있는 새 실행에 적용한다. |
| `conversation-memory/3` | 대화 전용 카페에서 다음 주 수업의 가상 손잡이가 29차례에 직접 만들어 본 기억으로 바뀌었다. 대화 전용 장면에서는 되돌아온 화제와 관련된 본인의 조건부 약속을 출처와 함께 재주입한다. 관련 관찰이나 장면 전환이 있으면 그 기록을 반영한다. 근거 없는 직접 회상 표현 일부를 검사한다. |
| `conversation-memory/4` | /3의 128차례 카페에서 태오는 2·56·89차례에 같은 수업 신청을 새 소식으로 말했다. 뒤의 두 차례 모두 자발적 휴식 후 회상을 비우면서 이미 소식을 들은 사람까지 잊었다. 대화 전용 장면은 휴식 중에도 최초 공개 원문과 실제 청자를 보존한다. 새 관찰·질문·청자가 없는 휴식에서 모두 들은 과거 사실 문장과 일치하는 재발표는 재생성한다. 명시적 회상, 질문, 달라진 사실은 계속 허용한다. |

| `sparse-voice/2` | 표현 단서가 빈 인물이 익숙한 화제에 응답할 때 완결된 말 한마디씩 생성한다. 배정한 박자에 따라 한 번에 담을 수 있는 말의 개수만 다르다. 대사 길이에는 글자 수 상한을 두지 않고 침묵은 빈 목록으로 받는다. 새 사건·상세 설명 요청·진행 중인 행동에는 기존 응답 형식을 쓴다. 생성 원본을 보관하고 공개 대사에는 각 항목 사이에 공백 한 칸만 넣는다. |

대화 지침은 `npc-dialogue/5`, 공통 시스템은 `npc-lab/12`다. 대화 기억 버전은 새 실행을 만들 때 고정한다. 저장한 이전 실행은 당시 경로로 재개할 수 있다. [Luna 전후 실측과 원문](reviews/topic-memory-2026-11-08/report.md)

정확한 문구와 이유는 [dialogue-policies.ts](../src/core/dialogue-policies.ts), 기본 버전은 [dialogue-policy.ts](../src/shared/dialogue-policy.ts)에 있다. 이미 기록된 버전의 본문을 수정하지 말고 `/3`, `/4`처럼 추가한다. 회귀 테스트의 고정 SHA-256은 기존 문구를 몰래 바꾸는 것을 감지한다. 새 버전마다 문제 출력, 가설, 비교 조건, 실제 결과, 부작용과 채택 여부를 이 문서와 검토 보고서에 추가한다.

실험 편집기의 **대화 반응 지침**에서 v1~v10을 고를 수 있다. v6~v10은 실험용이며 기본값은 v5다. JSON에서는 조건별 `dialoguePromptVersion`을 지정한다.

```json
{"id":"candidate","label":"반응 지침 v5","dialoguePromptVersion":"npc-dialogue/5","stopOnSilence":true}
```

생략하면 새 실행 생성 시 현재 기본값을 `run.variant`에 고정한다. 원본 spec은 보존하므로 실제 선택은 실행 스냅샷의 variant에서 확인한다. 대기 중에 기본값을 바꾸어도 생성된 실행은 따라 바뀌지 않는다. 이미 생성된 NPC 세션의 지침은 재개 시 다시 작성하지 않는다. 버전이 없던 이전 실행에서 아직 생성되지 않은 세션은 대조군 `/1`로 만든다. 이 경우 정확한 과거 `/5` 재현이라고 주장하지 않는다.

호출의 `metadata.promptVersion`은 실행 생성 때의 버전, `runtimePromptVersion`은 현재 실행 코드의 버전이다. `dialoguePromptVersion`과 `instructionsSha256`으로 선택한 정책과 실제 세션 지침을 확인한다. 과거에 없던 버전은 `null`로 남기며 현재 버전으로 소급 표기하지 않는다. `worldPromptVersion`은 실제 저장된 세계 세션의 본문과 동결 버전을 대조해 정하며 알 수 없으면 `null`이다. `outputSchemaSha256`은 실제 전송 스키마(설명 포함)의 해시다. 원본 세션 지침과 호출 입력은 기존 내보내기에 보존된다.

캐릭터 프로필의 지침도 출력에 영향을 준다. 예를 들어 ‘상대의 말을 요약한 뒤 의견을 말한다’, ‘합의할 선택지를 정리한다’는 프로필은 상담형 발화를 유도한다. 인물 고유 특성이면 보존하고, 모든 인물에 복사한 공통 문구라면 별도 프로필 버전으로 비교한다. 공통 정책과 프로필을 동시에 바꾼 결과를 공통 정책만의 효과로 주장하지 않는다.

수신 문구는 연기 지침과 별개다. [수신 호출 검토](reviews/receipt-delivery-2026-11-07/report.md)의 `/2`는 한 트랜잭션에서 확정한 발화와 규칙 결과만 합치고, 단일 관찰 `/1` 문구를 보존한다. `receivePromptVersion`으로 실제 호출을 추적하며 새 문구는 해시로 동결했다. 재시도는 기존 호출의 관찰 목록을 그대로 유지하고, 이미 수신한 내용을 새 입력으로 덧붙이지 않는다.

[인물별 말투 검토](reviews/character-voice-2026-11-07/report.md)는 사용자 피드백에 따라 고정 입력 160쌍과 24차례 대화 8회를 비교했다. /6~ /9와 반응 메모의 뚜렷한 개선 근거가 없어 기본값으로 채택하지 않았다. 실패한 출력 형식 실험도 보존한다. /7과 /9의 공통 문단 해시는 같으므로, 배치·추가 발화 지침까지 포함한 전체 세션의 `instructionsSha256`을 함께 확인한다. 정확한 후보 선택·실패 이유·다음 프로필 비교 방향을 보고서에 남겼다.

## 인물 프로필 비교

기본 예제의 [프로필·언어 안정화](reviews/harbor-stability-2026-11-07/report.md)에서 v2를 채택한 뒤, [윤·미루 후속 비교](reviews/harbor-refinement-2026-11-07/report.md)에서 `harbor-profile/4`를 채택했다. [harbor-profiles.ts](../src/shared/harbor-profiles.ts)의 `CURRENT_HARBOR_PROFILE`은 새 예제에 적용하며, `exampleSpec(model, effort, 'harbor-profile/2')`처럼 이전 버전을 재현할 수 있다. 버전은 동결된 `origin`을 상속한 뒤 해당 변경만 적용한다. 예제 ID `fog-harbor-profile4`와 저장된 전체 인물 설정으로 실행 당시 버전을 확인한다. 기존 사용자 설정은 자동 교체하지 않는다. 공통 NPC 지침 v5와 모델 설정은 이번 비교에서 그대로 유지했다.

v4는 일상 답변 뒤 임무 언급과 공유된 설명의 반복을 줄였다. 필요한 사실 질문·오해 정정·긴급 행동은 유지했다. 짧은 인사에서는 두 사람의 말투가 여전히 비슷하며, 수정하지 않은 도하가 일을 꺼내면 대화 전체가 다시 업무로 흐를 수 있다. 보고서는 이 한계와 v3의 부작용, 동일 입력 원문, 새 전이 사례와 재사용 사례를 구별해 보존한다.

```powershell
# 고정 입력 v2/v4, 후보 동결 후 만든 새 전이 사례
npm run dialogue:eval -- --cases evals/dialogue/harbor-transfer-profile2.json --candidate-cases evals/dialogue/harbor-transfer-profile4.json --baseline npc-dialogue/5 --candidate npc-dialogue/5 --split holdout --repetitions 2 --max-calls 24 --max-usd 1 --live

# 같은 시작 조건의 연속 대화. --live를 빼면 호출 없이 계획만 출력
node --env-file-if-exists=.env --import tsx scripts/harbor-live.ts --baseline-profile harbor-profile/2 --candidate-profile harbor-profile/4 --repetitions 2 --max-calls 140 --max-usd 1 --live
node --env-file-if-exists=.env --import tsx scripts/harbor-live.ts --baseline-profile harbor-profile/2 --candidate-profile harbor-profile/4 --scene break --repetitions 2 --max-calls 92 --max-usd 1 --live
```

인물별 성격·말투 피드백에 따른 후속 [프로필 검토](reviews/profile-voice-2026-11-07/report.md)는 공통 문단 제거 `/2`, 고유 말투·예문 강화 `/3`, 초안 편집과 생활극 집필 틀을 385회 API 호출로 비교했다. 일관된 개선 근거가 없어 원본 `seowol-profile/1`을 유지한다. [프로필 버전 구성](../assets/seowol/profile-versions.json)은 이유와 원본 파일을 기록하며 `current`만 바꿔 운영 프로필을 전환하는 기능은 아니다. 실패 후보와 실제 요청도 보존한다. 재현 방법은 [profile-review.md](../evals/dialogue/profile-review.md)에 있다.

## 고정 입력 비교

[cases.json](../evals/dialogue/cases.json)은 8개 개발 사례와 4개 보류 사례를 분리한다. 쉬운 부탁, 거절, 취향, 실망, 신난 긴 설명, 고객 응대, 모르는 정보, 자기 시간 보호, 사과, 직장 존댓말, 비공개 정보, 못 들은 질문을 포함한다. 참고 판정 기준과 타인의 비공개 프로필은 NPC 입력에 넣지 않는다. 보류 사례는 후보 문구를 동결한 뒤 실행한다.

```powershell
# 호출 없는 실행 계획
npm run dialogue:eval

# 동일 모델, 새 세션, 정책마다 사례당 3회
npm run dialogue:eval -- --live --split development --max-calls 48 --max-usd 2
npm run dialogue:eval -- --live --split holdout --max-calls 24 --max-usd 2

# 로그인된 Codex 실행 경로. 모델은 실제 설치 환경에서 지원해야 함
npm run dialogue:eval -- --adapter codex --model gpt-6-sol --live --split development --max-calls 48 --max-usd 2

# 이전 후보를 그대로 재실행
npm run dialogue:eval -- --candidate npc-dialogue/2

# 두 장면, 정책별 최대 18차례, 새 NPC 세션으로 이어지는 대화 검토
node --import tsx scripts/dialogue-soak.ts --adapter codex --model gpt-6-sol --live --max-usd 3
```

명시적으로 `--live`를 넣어야 모델을 호출한다. 실패·불확실 응답·사용량 누락·예산 도달 시 중단하고 자동 재요청하지 않는다. `max-usd`는 저장된 사용량과 로컬 가격표에 따른 다음 요청 차단선이며 마지막 한 요청은 초과할 수 있다. Codex 비용은 API 단가 환산치일 뿐 실제 구독 청구 금액이 아니다. 공급자·모델이 다른 표본은 별도 결과로 취급한다.

`.cache/dialogue-eval/`에 고정된 사례, 정책, 입력 전체, 응답 원문, 공급자 이벤트, 사용량, 입력 해시, A/B 매핑과 `review.md`를 남긴다. A/B의 순서와 먼저 호출하는 정책을 교차 배치한다. 검토 파일만 보면 정책 이름이 없지만 작성자가 매핑을 아는 검토는 **비독립 에이전트 검토**로 표시한다. 사람이 평가하지 않았다면 사람 평가라고 쓰지 않는다. 실패는 삭제하거나 완료된 표본 수에 포함하지 않는다.

## 채택 기준과 다음 실험

각 비교에 `A/B/tie/neither`와 근거 인용을 적는다. ① 문맥에 맞는 대꾸 ② 과잉 해설·선제 대안 ③ 고유 목소리·존댓말 ④ 필요한 정보 ⑤ 지식·행동 권한을 따로 본다. 짧은 응답을 자동 우승시키지 않는다. 설정 위반이나 필요한 답의 누락은 자연스러움이 좋아도 별도로 남긴다.

단일 차례 비교는 긴 대화의 리듬을 보장하지 않는다. 기본 정책을 바꾸기 전 새 세션의 여러 차례 대화도 읽는다. 반복 상담, 질문 연쇄, 행동만 반복하는 침묵, 즉각 화해, 같은 말투로 수렴하는지 확인한다. 새 문제가 생기면 사례를 추가하고 데이터셋 버전을 올린다. 고정 입력에 맞춘 문장 외우기나 출력 후 강제 절단은 사용하지 않는다.

## 침묵과 장면 종료

단일 공간 NPC는 `speech`와 `action`을 둘 다 빈 문자열로 내어 차례를 넘길 수 있다. 이는 검증 실패가 아니다. 원본 선택·호출·사용량은 보존하지만 빈 내용으로 다른 NPC의 수신 호출을 만들지 않는다. 화면에는 대사를 지어 넣는 대신 ‘발언·행동 없이 차례를 넘김’이라는 기록 표시를 한다. 기존 `speechCount`는 말이 있는 문장 수가 아니라 NPC 선택 차례 수이므로 실제 발언 수는 원문에서 따로 세어야 한다.

`stopOnSilence:true`는 **환경 꺼짐**에서만 적용한다. 마지막 실제 발언·행동·상황 뒤 모든 NPC가 한 번 이상 연속해서 조용히 차례를 넘겼고 예정된 미적용 사건이 없으면 `conversation_idle`로 끝난다. 한 인물의 침묵, 몸짓이 있는 차례, 규칙·AI 세계·분산 공간은 이 종료 조건을 적용하지 않는다. 기본값은 꺼짐이며 기존 고정 발화 수 실험은 유지한다. 새 일상 예제와 대화 검토 도구만 이 옵션을 켠다. 분산 공간의 선택/활동 계약은 이번에 변경하지 않았다.

첫 단계는 [v1~v3 검토](reviews/dialogue-2026-11-07/report.md), API 복구 뒤 반복·행동 지속 및 서월 검증은 [v4~v5 검토](reviews/dialogue-continuity-2026-11-07/report.md)에 남긴다. 실패한 후보와 전이 세트 재사용 한계도 보존한다.

세계 출력의 반복은 [세계 관찰 검토](reviews/world-observations-2026-11-07/report.md)에서 /2 대 /4로 비교했다. 이후 [긴 대화 검토](reviews/long-dialogue-2026-11-07/report.md)에서 /4의 시간 정지와 대화의 사건화 문제를 확인해 /6을 기본값으로 채택했다. `worldPromptVersion`으로 조건마다 선택한다. 이미 생성된 세계 세션은 그대로 유지하고, 버전 필드가 없던 실행에서 아직 만들지 않은 세계 세션은 /2를 쓴다. 세계 고정 입력은 `npm run world:eval`로 재현한다.

세계 /6은 말·행동 모두 빈 차례의 응답 스키마와 런타임 검증에서 `elapsedSeconds:1`을 요구한다. 이것은 고정된 시뮬레이션 규칙이며 실제 API 지연 시간이 아니다. 일반 행동의 시간·물리 결과는 기존 판정 경계를 사용한다. /1~ /5 및 알 수 없는 저장 세션은 기존 시간 계약을 유지한다. 요청마다 실제 스키마 해시를 기록하므로 /6도 조용한 차례와 일반 차례의 해시가 다르다.

진행자는 성격·발화 내용을 만들지 않는다. 허용 후보를 정하는 장기 배제 방지 규칙도 유지한다. 기본 `npm run director:eval`은 동결된 /2 대 /3 스키마 비교다. 현재 /4의 공개 시작 장면 비교는 [진행자 맥락 보고서](reviews/director-context-2026-11-07/report.md)의 `--comparison context` 명령으로 재현한다. 당사자 파악 20개 표본에서 /3의 2개에서 /4의 20개로 개선됐고, 이어지는 대화 2회에서 질문 뒤 당사자가 바로 답했다. 후보 ID 준수·당사자 선택을 인물 말투의 자연스러움 점수로 해석하지 않는다.

평가 절차는 [OpenAI의 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)과 [코드로 관리하는 프롬프트 지침](https://developers.openai.com/api/docs/guides/prompting)을 참고했다. 이 저장소의 통과 여부는 자체 실행 증거이며 공식 지침 자체가 품질을 보증하지 않는다.

## 연속성과 행동 지속 비교

`continuity-cases.json`은 끝난 용건과 아직 답하지 않은 질문을 구별한다. `continuity-transfer.json`은 다른 지속 활동, 새 제안, 남은 불만, 자발적 관심·소식의 6개 사례다. v4 검토에 사용한 뒤 v5에서 재사용하므로 이후에는 독립 holdout으로 부르지 않는다. `follow-through-cases.json`은 합의 뒤 실행과 이미 끝난 행동을 구별하는 회귀 세트다.

`dialogue-soak.ts`는 원본의 환경 꺼짐/AI 모드·세계 판정 자료·예정 사건을 유지한다. 규칙·분산 공간은 이 도구의 대상이 아니다. 각 반복은 별도 폴더로 보존한다.

```powershell
# 세계 관찰과 실제 행동 결과를 포함, 정책별 2회. 계획만 보려면 --live 제거
node --env-file-if-exists=.env --import tsx scripts/dialogue-soak.ts --specs evals/dialogue/observed-conversations.json --baseline npc-dialogue/3 --candidate npc-dialogue/5 --world-model gpt-6-luna --repetitions 2 --max-calls 144 --max-usd 2 --live

# 고정된 후속 행동 회귀
npm run dialogue:eval -- --cases evals/dialogue/follow-through-cases.json --baseline npc-dialogue/4 --candidate npc-dialogue/5 --split all --repetitions 2 --max-calls 16 --max-usd 1 --live
```
