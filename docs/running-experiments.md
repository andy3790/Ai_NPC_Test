# 실험 실행과 운영

설치·서버 시작은 [README](../README.md), API 키·모델 지원표는 [API 실행 안내](openai-api.md), 설정 필드는 [JSON 가이드](experiment-json-guide.md)에 있습니다. 명령은 프로젝트 루트에서 실행합니다.

## 실행 경로와 저장 위치

서버 하나는 `codex`, `openai`, `mock` 중 하나의 어댑터를 사용합니다. 실험 JSON으로 어댑터를 바꾸지 않습니다. 동일 설정을 다른 서버에서 실행한 뒤 통합 기록에서 비교할 수 있습니다.

| 설정 | 적용 |
|---|---|
| `serve --adapter` | `codex`, `openai`, `mock`. `--mock`도 지원하지만 충돌하는 옵션은 거부 |
| `serve --port` | CLI 기본값 4317. `start:openai`는 4318 |
| `serve --data` | 현재 DB·실행 보조 파일 저장 폴더 |
| `NPC_LAB_DATA` | `--data` 미지정 시 적용. 둘 다 없으면 API는 `data/openai`, 나머지는 `data` |
| `NPC_LAB_ADAPTER` | 어댑터 옵션 미지정 시 적용 |
| `PORT` | `npm start`/`npm run dev` 포트. CLI `serve`는 자체 `--port` 기본값 사용 |
| `serve --no-history` | 현재 DB만 조회. 다른 기록을 삭제하는 옵션이 아님 |

같은 데이터 폴더를 두 서버가 동시에 열지 못하도록 `server.lock`을 사용합니다. 포트와 DB를 모두 분리하세요. `.env`는 `start:openai`와 `smoke:openai`에서 자동으로 읽습니다. 일반 `npm run cli -- serve`는 셸 환경 변수를 사용하며 `.env`를 자동으로 읽지 않습니다.

브라우저를 닫아도 서버 프로세스가 살아 있으면 실험은 계속됩니다. API 페이지에서 입력한 개인 키도 서버 종료까지 유지합니다. 서버 재시작 후 진행 중 기록은 일시정지 상태로 복구하며 개인 키 실험은 원래 키를 다시 입력해야 재개합니다. 개인 키 교체·해제는 새 실험에만 적용합니다. 우선순위와 CLI의 서버 키 사용 범위는 [API 실행 안내](openai-api.md)를 참고하세요.

## Codex CLI 연결

설치·로그인한 Codex CLI에서 `codex --version`이 실행되는지 먼저 확인하세요. 앱은 `codex app-server --listen stdio://`를 자식 프로세스로 시작하고 모델 목록·독립 thread·turn·사용량 이벤트를 사용합니다. 프로토콜 배경은 공식 [App Server 문서](https://learn.chatgpt.com/docs/app-server)에 있습니다.

Windows는 표준 npm 설치의 네이티브 실행 파일 또는 JS 진입점을 찾아 사용합니다. 다른 위치에 설치했다면 서버 환경 변수 `CODEX_BIN`에 실제 codex.exe 또는 codex.js 경로를 지정합니다. cmd/ps1/bat 래퍼 경로는 받지 않습니다. 지원되지 않는 프로토콜·CLI 설정 오류는 원본 오류를 남기며 다른 모델로 자동 대체하지 않습니다.

NPC 작업 폴더를 분리하고 읽기 전용 샌드박스·승인 거부·프로젝트 지시문 배제와 셸·웹·앱·연결 도구 제한을 적용합니다. Codex의 문맥 압축은 유지하며 발생 이벤트를 기록합니다. 재접속으로 사용량 누적 기준이나 완료 여부를 확인할 수 없으면 해당 계측을 추측하지 않습니다.

## 웹에서 실행

1. **새 실험**에서 예제·JSON을 불러와 시나리오·캐릭터·조건을 폼이나 범위별 JSON으로 편집합니다.
2. NPC와 보조 역할의 모델·추론을 검증합니다. `variants × repetitions`, 발화 한도, 동시 호출, 환경 방식, 평가 간격을 확인합니다.
3. 즉시 시작하거나 일시정지 상태로 생성합니다. 생성 시 원본 설정·적용 조건을 스냅샷·해시로 고정합니다.
4. 묶음에서 대화·평가·세계 상태·호출·실행 설정을 확인합니다. 분산 공간은 장소와 NPC 관찰 관점을 선택할 수 있습니다.
5. 묶음을 선택해 비교·내보냅니다. 검색과 삭제는 [기록 관리](run-management.md)를 참고하세요.

편집 설정은 이후 생성할 실험에만 적용됩니다. 실행 중 모델·캐릭터·장소를 변경하지 않습니다. **실행 설정** 화면은 해당 테스트의 원본을 보여 줍니다.

## 대화 전달과 기억

| 옵션 | 동작 |
|---|---|
| `batched_on_turn` | 수신함에 쌓은 미수신 기록을 자기 차례의 발화 요청에 순서대로 포함. 별도 수신 호출 없음 |
| `per_utterance` | 확정 기록마다 실제 수신 대상의 동일 세션에 확인 호출. 필요한 확인이 끝나야 다음 단계 진행 |
| `initial_only` | 처음 설정한 NPC 세션 유지 |
| `reinject_on_speech` | 본인의 발화·행동 선택마다 원본 설정 추가 상기. 수신 확인에는 추가 상기하지 않음 |

묶음끼리 기록·세션을 공유하지 않습니다. 이미 받은 기록이나 자기 출력을 중복 입력하지 않습니다. 수신 확인은 공개 대화에 섞이지 않습니다. 단일 공간은 일반적으로 나머지 모든 NPC, 분산 공간·범위 지정 사건은 실제 관찰 대상만 수신합니다.

모아 전달의 마지막 미처리 수신함은 그대로 남기며 종료 후 확인 호출을 추가하지 않습니다. API의 `initial_only`도 역할 `instructions`는 매 요청 포함하므로 Codex와 내부 프롬프트 운용이 완전히 같지는 않습니다.

## 제어와 복구

| 제어 | 동작 |
|---|---|
| 일시정지 | 발화·환경·필수 전달의 안정된 경계에서 멈춤. 이미 시작한 분산 동시 선택은 끝날 수 있음 |
| 재개 | 미확정 호출과 체크포인트 대조 후 계속 진행 |
| 한 발화 진행 | NPC 선택 1회와 필요한 엔진·전달 처리 후 정지. 평가 경계이면 평가도 가능 |
| 중단 | 호출 상태를 보존하고 진행 중단. 종료된 실행을 새 설정으로 이어 쓰는 기능은 없음 |
| 상황 투입 | 안정된 일시정지 상태에서 관찰 사건 추가. 대상 장소·NPC 지정 가능 |
| 평가 | 미평가 구간과 실패한 평가 처리. 발화·세계 상태를 고치지 않음 |

`maxUtterances`는 대사 없는 행동도 포함한 NPC 선택 수입니다. 환경 결과·수신·평가·진행자는 포함하지 않습니다. `rules`는 목표 달성으로 조기 종료할 수 있습니다. 분산 공간의 한 발화 진행은 미래 완료 시각까지 건너뛰지 않으며 종료 시 작업·답장은 미완료로 보존됩니다.

일부 수신·병렬 호출 실패 시 성공한 부분은 유지하고 일시정지합니다. 재개는 미완료 부분만 처리합니다. 전송 결과가 불확실한 호출은 기존 thread/turn 또는 response ID로 대조하며, 확인할 수 없으면 자동 재전송하지 않습니다. 미확정 분산 선택·결과 복구 중에는 수동 사건을 끼워 넣을 수 없습니다.

## CLI 명령

제어 명령에는 실행 중인 서버가 필요합니다. 주소 기본값은 `http://127.0.0.1:4317`입니다. `<묶음-ID>`를 반환된 실제 ID로 바꾸세요.

```powershell
npm run cli -- --url http://127.0.0.1:4318 models
npm run cli -- --url http://127.0.0.1:4318 example --out examples/local-example.json
npm run cli -- --url http://127.0.0.1:4318 validate --config examples/local-example.json
npm run cli -- --url http://127.0.0.1:4318 run --config examples/local-example.json --paused
npm run cli -- --url http://127.0.0.1:4318 status
npm run cli -- --url http://127.0.0.1:4318 status <묶음-ID>
npm run cli -- --url http://127.0.0.1:4318 step <묶음-ID>
npm run cli -- --url http://127.0.0.1:4318 resume <묶음-ID>
npm run cli -- --url http://127.0.0.1:4318 pause <묶음-ID>
npm run cli -- --url http://127.0.0.1:4318 inject <묶음-ID> --text "복도에서 짧은 신호음이 들린다."
npm run cli -- --url http://127.0.0.1:4318 evaluate <묶음-ID>
npm run cli -- --url http://127.0.0.1:4318 analysis --runs <묶음-ID>,<다른-묶음-ID>
npm run cli -- --url http://127.0.0.1:4318 export <묶음-ID> --out exports/my-run
npm run cli -- --url http://127.0.0.1:4318 stop <묶음-ID>
```

`--paused`를 빼면 바로 시작합니다. `models`, `validate`, 일시정지 생성은 발화 추론을 시작하지 않지만 모델 목록 조회가 발생할 수 있습니다. `inject --location ID`와 `--npc ID`는 하나만 사용하고 생략하면 전체 관찰입니다. 삭제 CLI는 없으며 웹 또는 [삭제 API](api.md)를 사용합니다.

## 문제 해결

| 현상 | 확인 |
|---|---|
| 이전 기록이 안 보임 | 현재 DB·보관소·검색 루트·기록 새로고침 |
| API 대신 Codex로 실행 | 서버 어댑터와 CLI `--url` |
| 모델·추론 검증 실패 | 서버 모델 목록, NPC 재정의, 보조 역할 설정 |
| 일찍 종료됨 | 규칙 목표 조기 종료, 오류에 따른 정지, 행동만 있는 차례 포함 여부 |
| 목표 달성률 없음 | 자동 상태 목표는 `rules`에만 존재 |
| 분산 대화가 안 보임 | 장소·관찰 관점 필터와 수신 완료 여부 |
| 사용량·비용이 비어 있음 | 미계측·미등록 단가·진행 중 호출·모의 실행. [지표 설명](data-and-evaluation.md) 참고 |
| 데이터 폴더가 사용 중 | 실행 중 서버 확인. 살아 있는 서버의 잠금 파일을 임의 삭제하지 않음 |

장기 보관·다른 컴퓨터 이전은 [백업 절차](run-management.md#백업과-이전)를, 공개할 기록의 범위는 [보안과 데이터](../SECURITY.md)를 참고하세요.
