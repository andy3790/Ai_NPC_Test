# Codex 테스트 세션 정리

현재 정책은 `codex-session-cleanup/2`이며 2026-11-07에 적용했습니다.

기존 구현은 NPC 세션을 실험 뒤에도 남겼고, 매번 새로 만드는 진행자 세션은 마지막 ID만 보관했습니다. 고정 입력 비교 도구도 생성한 세션을 삭제하지 않았습니다. 이제 결과를 프로젝트에 저장한 뒤 Codex의 세션 기록을 정리합니다. 프롬프트 본문·버전은 변경하지 않았습니다.

| 상황 | 정리 시점 |
| --- | --- |
| 실행 완료·사용자의 중단 | 진행 중인 호출이 종료된 뒤 NPC·세계·평가자·진행자 세션 삭제 |
| 새 세션을 쓰는 진행자 호출 | 결과·실패가 기록된 즉시 삭제. 다음 세션 생성 전에 정리를 재시도하고, 계속 실패하면 기존 ID를 보존하고 실행을 일시정지 |
| UI 일시정지·서버의 정상 종료 | 재개할 NPC·세계 세션 유지. 완료된 진행자 세션은 삭제 |
| 결과가 불확실한 진행자 호출 | 실행이 재개 가능하면 유지. 명시적으로 실행을 중단하면 삭제 |
| 독립 CLI 테스트 종료·실패·Ctrl+C/SIGTERM | 실행 중인 호출 종료 뒤 세션 삭제. 고정 입력 비교는 각 표본 저장 직후 삭제하고, 다음 표본을 시작할 때도 이전 ID가 정리됐는지 확인 |
| 삭제 실패·프로세스 강제 종료 | 실패/소유 기록을 보존. 서버 시작·종료·다음 교체 또는 아래 정리 명령에서 재시도 |

아카이브 이동 대신 영구 삭제 RPC를 사용합니다. [Codex App Server의 `thread/delete`](https://learn.chatgpt.com/docs/app-server#delete-a-thread)는 저장된 세션의 기록과 메타데이터를 제거합니다. CLI 0.157.1에서 삭제된 ID의 `thread/read`는 `thread not loaded`를 반환하므로, 재개 조회의 `no rollout found`까지 확인해서 이미 없는 세션을 구분합니다. 권한·연결 오류는 삭제 완료로 처리하지 않습니다.

삭제 전 호출 기록의 ID와 Codex가 반환하는 작업 경로를 함께 검사합니다. 프로젝트의 실험 DB·원문·사용량·프롬프트 해시·평가 기록은 남습니다. `run.sessionCleanup` 및 `session/cleanup` 이벤트에서 성공·누락·실패를 확인할 수 있습니다. 늦게 도착하는 사용량 이벤트는 세션 삭제 뒤에도 원래 호출에 기록합니다. OpenAI API 세션에는 이 정책을 적용하지 않습니다.

## 기존 테스트 기록 정리

```powershell
npm run sessions:cleanup
npm run sessions:cleanup -- --apply
```

첫 명령은 대상만 확인하고, `--apply`가 있을 때 삭제합니다. `data/`, `reports/`, `.cache/`의 실험 DB와 Codex 고정 입력 비교의 이벤트·세션 소유 기록을 읽습니다. 실행 중인 서버, 재개 가능한 실험, 아직 실행 중인 테스트 프로세스, 소유 경로가 다른 세션은 삭제하지 않습니다. 전역 세션 폴더를 직접 지우지 않습니다.

고정 입력 비교는 세션을 만들자마자 `sessions.jsonl`에 ID·작업 경로·프로세스 ID를 기록합니다. 강제 종료로 `finally`가 실행되지 않아도 프로세스 종료가 확인되면 위 명령으로 정리할 수 있습니다. 이전 형식의 비교 기록은 종료된 `manifest.json`과 이벤트에서 소유가 입증되는 ID만 정리합니다. 다른 저장 위치나 소유 기록이 없는 세션은 자동 추측하지 않습니다.

`/2`부터 독립 엔진 테스트는 첫 세션을 열기 전에 실행별 소유 PID와 폴더를 실험 DB에 기록합니다. 프로세스가 강제 종료되면 다음 정리 명령이 해당 실행의 미종료 세션도 회수합니다. 실행 중인 테스트와 서버, 소유 기록이 없는 일시정지 실험은 보호합니다. 실제 CLI 통합 검사의 전용 폴더와 자체 소유 기록을 남긴 단독 표본도 검사합니다.

결과는 `.cache/codex-session-cleanup/preview.json`, `applied.json`에 저장합니다. 앱의 실험 DB는 이 일괄 정리 명령에서 읽기 전용으로 엽니다.

## 검증

```powershell
npx tsx --test tests/session-cleanup.test.ts tests/test-sessions.test.ts tests/protocol.test.ts
npm run smoke:codex-cleanup
```

두 번째 명령은 실제 Codex 모델을 7회 호출합니다. NPC 일시정지·CLI 재시작·재개, 첫 진행자 삭제 뒤 두 번째 진행자 생성, 실행의 자연 완료와 명시적 중단, 단독 표본 교체, 미사용 빈 세션을 검사합니다. 세션 ID가 포함된 상세 증거는 로컬 `.cache/history-test-codex-cleanup-*`에 남습니다.

2026-11-07 기존 기록 감사: 실험 DB 18개 실행 사본과 고정 입력 비교에서 정리 대상 ID 242개를 찾았습니다. 현재 CLI 저장소의 조회·복구 조회 결과 모두 `missing`이었으며, 이 수를 새로 삭제한 세션 수로 집계하지 않습니다. 재개 가능성이 있는 14개 ID는 정리 범위에서 제외했습니다. 실제 검증에서 새로 생성한 세션은 삭제 후 재조회로 부재를 확인했습니다.

`/1`은 전체 회귀 테스트 206개를 통과했고, CLI 0.157.1의 통합 검사에서 4회 호출로 세션 6개를 삭제했습니다. `/2`의 실제 검사는 같은 CLI와 `gpt-6-luna`의 낮은 추론 설정에서 7회 호출했습니다. 자연 완료·중단에 쓰인 엔진 세션 8개와 독립 표본 2개 모두 같은 ID의 재조회에서 부재를 확인했습니다. 별도 회귀 검사는 삭제가 계속 실패할 때 다음 세션을 생성하지 않는지, PID가 종료된 독립 테스트와 아직 재개 가능한 일반 실험을 구분하는지 검증합니다.

실제 CLI 검사 폴더까지 확장한 `/2` 감사에서는 48개 DB와 표본 기록을 검사했습니다. 정리 대상 270개가 모두 이미 삭제된 상태였고, 삭제 대기와 건너뛴 데이터 원본은 0개였습니다. 재개 가능한 실행 등에 속한 ID 14개는 보호했습니다.
