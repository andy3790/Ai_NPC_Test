# 서월 성격별 문체 실험 · 2026-11-06 UTC

## 문제와 수정 기준

사용자 피드백은 존댓말·단어 선택뿐 아니라 **내용을 배치하고 상대에게 말하는 방식**이 계속 AI 같다는 것이었다. 이전의 행동 개선과 문체 개선을 구별해서 검토했다. 거절·협상이 생겼다는 사실만으로 자연스럽다고 평가하지 않는다.

이번에 직접 읽은 기준은 다음과 같다.

- 상대 말에 대꾸한 뒤 자기 입장·설명·대안·다음 부탁을 한꺼번에 붙이는가.
- 프로필의 정보를 공개할 이유도 없이 첫 발화부터 설명하는가.
- 질문이나 부탁 뒤에 상대의 답을 기다리는가, 예상 답변까지 혼자 처리하는가.
- 각자 신경 쓰는 것이 다른가, 같은 문제를 함께 정리하는 상담자로 모이는가.
- 감정과 몸짓을 매번 해설하는가, 무발언이나 평범한 답도 나오는가.
- 캐릭터 말끝을 가려도 무엇에 관심을 두고 어떻게 버티는지 차이가 있는가.

문장 길이·욕설·반말 비율을 자연스러움 점수로 환산하지 않았다. 짧은 대사도 기계적일 수 있고 길게 투덜거리는 말도 자연스러울 수 있다.

## 새 인물

기존 인물의 성격이나 세계 법칙을 바꾸지 않고 새 시험 인물 셋을 만들었다. 이들은 정사에 자동 편입되는 인물이 아니다. 프로필 원본은 [experimental-cast.json](../assets/seowol/experimental-cast.json)이다.

| 인물 | 생활과 말투 | 내용을 고르는 방식 |
|---|---|---|
| 백도하 | 23세 배송기사·밴드 베이시스트. 친한 두 사람에게 반말 | 인정받고 싶은데 혼나기는 싫다. 자기 잘못의 크기를 줄이거나, 지적의 곁가지부터 반박한다. |
| 임소진 | 31세 수리기사. 신경질적인 반말 | 남의 부탁이 자기 시간·공구를 침범하는지 먼저 듣는다. 잘못된 용어에 꽂혀 원래 질문을 놓칠 수 있다. |
| 고복만 | 외견 59세, 존재 기간 41년의 현상기원 중고상. 소진에게 하오체, 도하에게 해라체 | 자기 물건의 손상과 체면에 민감하다. 남의 문제를 중재하기보다 자기가 아끼는 물건을 챙긴다. |

세 사람은 친분과 서로 허용한 반말 관계를 명시했다. 고복만은 모체 현상과 독립해 살아가는 인격이며 별도 이능은 없다. 다른 두 사람도 이능이 없고 수리는 학습한 기술이다. 차폐는 인지에 작용하며 물리적 손상을 막지 않는다. 기존 세력의 간부·세계 비밀의 해답·기존 인물과의 새 공유 과거를 붙이지 않았다.

## 장면과 변경 과정

**앰프 장면**에서는 빌려 간 기기의 모서리를 손상시킨 도하, 저녁을 먹으려는 소진, 물건 주인 복만이 만난다. 테이프 안쪽 손상과 실제 고장은 세계 판정 자료에만 주고, 소진·복만은 사전에 운반 사고를 모른다. 즉시 사고를 자백하거나 수리를 받아 주도록 정하지 않았다.

**저녁 장면**은 별개의 세션이다. 도하가 연습 영상을 틀고 다른 두 사람이 식사한다. 대여·손상 사건을 기억에서 제거했고, 합의·수리·마감 같은 외부 목표 없이 취향과 관계만으로 대화가 이어지는지 본다.

| 지침 | 변경 |
|---|---|
| v2 | 이전 공통 말투 지침. 공유 맥락 생략, 짧고 긴 말의 혼합, 상투적 행동 묘사 억제 |
| v3 | 상대의 말을 항목별로 처리하지 않고 자기 관심에서 반응하도록 변경 |
| v4 | 아는 설정을 공개할 답안으로 취급하지 않음. 자기에게 불리한 정보의 축소·회피도 가능. 상대의 반응이 들어올 지점에서 발화를 끝냄 |

v4는 거짓말을 매번 하게 만드는 규칙이 아니다. 허위 발언이 세계의 사실을 바꾸지도 않는다. 실제 고장·능력·과거는 유지하며, 그 사실을 상대에게 어떻게 말할지와 구별한다.

## 실제 출력에서 관찰한 점

다음 인용은 사람이 고친 예시가 아니라 실제 저장된 API 출력이다. 비교되는 장면의 프로필·예시·모델은 같고 공통 반응 지침만 다르다. 다만 생성은 확률적이므로 한 표본의 차이 전체를 지침 효과라고 단정하지 않는다.

v2 대조군 A의 첫 도하 발화는 사고 경위·손상·확인한 것·확인하지 않은 것을 한 번에 보고했다.

> 그거 낮에 옮기다가 턱에서 한 번 떨어뜨렸어. 모서리 찍혀서 감은 거야. 들고 올 땐 덜렁거리는 소리는 안 났는데, 아직 켜 보진 않았어.

v4 실험 D의 같은 시작에서는 다음만 말했다.

> 모서리 좀 찍혀서 감았어. 들고 오다가 턱을 못 봐서.

이후 손상이 드러나자 복만이 ‘좀 찍혔다’는 축소 표현 자체를 물고 늘어졌다. 정보를 먼저 전부 공개하고 사후 처리로 넘어가는 대신, 뒤늦게 드러난 정보가 다음 대화의 이유가 됐다.

D의 도하·소진 대화:

> 도하: 먹어. 켜 보는 건 나도 해. 이상하면 그때 좀 들어봐 줘.
>
> 소진: 그게 봐 달라는 거잖아. 밥 먹는 옆에서 켜지 마.

도하는 본인 부탁을 작은 일로 포장하고 소진은 그 포장을 받아들이지 않는다. 도하에게 아직 여러 용건을 붙이는 경향이 남지만, 두 사람이 같은 의제를 나눠 정리하는 흐름은 약해졌다.

중간 지침 B에서도 다음 대화는 관찰됐다.

> 소진: 아저씨, 그거 오늘 여기 두고 갈 생각은 하지 마. 맡길 거면 내일 가져와.
>
> 복만: 내가 들고 가오. 아직 맡긴다는 말도 안 했는데.

v4 저녁 장면 E에서는 소진이 도하의 설명을 끝까지 받아 주지 않고 “잠깐 말 좀 멈춰 봐. 들어보게.”라고 했다. 짧은 명령 하나가 나온 사실만으로 전체 장면의 자연스러움을 보증하지는 않는다.

## 남은 한계

- 도하는 ‘대답 → 해명 → 부탁’을 한 번에 묶기도 한다. 말끝을 바꾸는 것만으로 이 버릇이 사라지지는 않는다.
- 고복만은 손상 장면에서 꾸짖는 보호자처럼 길게 설명하는 경우가 있다. 하오체 자체가 살아 있는 인물성을 보증하지 않는다.
- 저녁 장면도 녹음·연주를 개선해 주는 상담으로 수렴할 수 있다. 캐릭터들이 반드시 해결책을 내지 않는지 장기 표본이 더 필요하다.
- 세계 엔진이 NPC의 동작을 다시 중계하는 경우가 남는다. 대사 문체와 별개로 화면에서 기계적인 인상을 만드는 요인이다.
- 자동으로 검증한 것은 스키마·비공개 정보 분리·세계 경계다. 자연스러움은 전체 원문을 사람이 판단해야 한다.
- 이번에는 기존 실행 서버의 `npc-lab/5`에서 모든 조건을 고정했다. 입력은 생성된 실험 JSON과 대조했으며 새 공통 반응 지침은 인물 프로필로 전달했다. 재시작한 `npc-lab/6` 전체 동작을 검증한 결과는 아니다.
- 기존 정사 인물 다섯 명의 팩에도 v4를 적용했지만, 그 인물들에 대한 v4 실제 API 검토는 이번 표본에 포함하지 않는다.

## 실행 기록과 재현

실험 화면의 이름에서 `성격실험 A`~`E`를 찾을 수 있다. 종료 상태·비용·전체 대화는 아래 완료 기록에 남긴다. 원본 호출·설정 스냅샷은 `.cache/seowol-voice-review/`에 보존하며 키는 내보내지 않는다.

실행 파일과 명령은 [서월 실행 팩](../assets/seowol/README.md)을 참고한다. v4 기본 파일은 `strong-voices.json`, `strong-voices-dinner.json`이며, v2·v3 대조군도 함께 보존한다. 이미 생성한 세션에는 변경된 프로필이 소급되지 않으므로 새 실험으로 비교한다.

## 완료 기록

NPC Sol low, 진행자 Luna low, 세계 엔진 Luna medium. 독립 평가·자동 상황 발생은 끄고 각 실험을 새 세션에서 실행했다. 모든 조건이 오류·수동 재시도 없이 완료됐다. 터미널 API 연결은 실패했으나 기존 앱의 정상 실험 화면에서 실제 API를 실행했다. 파일 가져오기는 브라우저 권한 제한으로 실패하여 JSON 편집기에 입력했고, 저장된 시나리오 전체를 생성 파일과 대조해 차이가 없음을 확인했다.

E에서는 마지막 다섯 차례가 영상 듣기·식사 동작으로 이어졌다. 영상이 진행 중인 상황에서 침묵 자체는 가능하지만, 반복된 관찰이 재미를 만들지는 못했다. 이 결과를 문체 개선 성공으로 세지 않는다. 발화 억제와 지속되는 장면의 관찰 방식은 별개 과제로 남는다.

조건마다 표본은 한 번이다. 고정된 문장의 재현이나 사용자 취향에 대한 보증이 아니며 모델 간 품질 비교도 아니다. 전체 원문을 편집하지 않고 저장했다.

검증: 기존 설정 보존·비공개 정보 격리·비교 조건 고정·장면 간 기억 분리를 포함한 관련 검사 8개, TypeScript 타입 검사, 공개 파일 검사, git diff --check 통과. 이번 변경은 실행 팩과 그 생성 코드이며 서버 동작 코드를 추가로 변경하지 않았다.
