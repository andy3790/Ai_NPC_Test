# Windows 응답 기록 교체 오류 · 2026-11-07

윤·미루 프로필 회귀 검사 중 기존 OpenAI 어댑터의 임시 JSON 파일 `rename`이 `EPERM`으로 실패하며 실행이 `paused` 또는 `uncertain`이 되는 문제가 재현됐다. 전체 검사에서는 187개 중 1개, 해당 파일만 재실행했을 때는 15개 중 1개가 실패했다. 서로 다른 임시 폴더의 분산 실행 테스트에서 발생했다. 특정 파일 잠금 주체까지 확인한 것은 아니다.

`replaceFileSync`는 Windows의 `EPERM`·`EACCES`·`EBUSY`에 대해서만 로컬 원자적 교체를 10·20·40·80·160ms 뒤 재시도한다. 동기 저장 경로여서 최대 대기 310ms로 제한한다. 기존 파일을 먼저 지우거나 직접 덮어쓰지 않는다. 제한 후에도 실패하면 같은 오류를 전달한다. 다른 오류와 다른 OS에서는 즉시 실패한다.

이 재시도는 파일 교체에만 적용한다. 네트워크 실패의 자동 재전송 금지, 기존 호출 ID 중복 전송 방지, 응답 ID를 이용한 복구 계약은 유지한다.

검증은 일시 잠금 중 기존 파일 유지와 성공 후 새 내용, 지속 잠금의 유한 대기와 양쪽 파일 보존, 비대상 오류 즉시 전파를 다룬다. 새 테스트와 기존 OpenAI 어댑터 테스트 18개가 통과했고 이후 전체 190개도 통과했다. 실제 API 대화 비교는 이 저장 보완 전에 완료했으며, 이번 프로필 품질 개선을 저장 재시도의 효과로 해석하지 않는다.
