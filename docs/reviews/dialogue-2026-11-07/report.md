# 대화 반응 지침과 침묵 처리 검토 · 2026-11-07 KST

## 결론

`npc-dialogue/3`을 새 실험의 기본 후보로 적용한다. 한 번에 대답·해명·대안을 묶는 경향을 줄이는 사례를 확인했고, 필요한 긴 설명·존댓말·모르는 정보에 대한 답을 유지했다. **사람 평가나 모든 장면에서의 자연스러움을 입증한 결과는 아니다.** 대부분의 단일 차례 응답은 대조군과 큰 차이가 없었고, 긴 대화의 확인 반복과 몸짓 반복은 남았다.

실제 대화 도중 `speech:"", action:""`가 나오면 검증 오류로 멈추는 문제를 발견해 수정했다. 빈 내용의 수신 호출을 만들지 않으며, 대화 전용 실험에서는 모든 인물이 조용해졌을 때 종료하는 옵션을 추가했다. 오류 발생 기록도 보존한다.

## 조건과 원문

실제 호출은 로그인된 **Codex CLI / gpt-6-sol / low**다. OpenAI API의 `gpt-6.1-sol`은 모델 목록 조회에 성공했지만 첫 생성이 `credit_balance_exhausted`로 거절됐다. 따라서 API 품질 결과는 없다. CLI에서 지원되지 않는 `gpt-6.1-sol` 계획도 0회 호출로 종료했다. 모델을 바꿔 성공한 결과를 API 모델의 검증으로 섞지 않는다.

단일 차례는 정책 외의 세계·인물·입력·모델·추론·출력 형식을 고정하고 매번 새 세션을 썼다. A/B 순서와 먼저 호출하는 조건을 교차 배치했다. 작성 에이전트가 원문을 읽은 **비독립 정성 검토**이며 사람의 블라인드 평가가 아니다. 자동 자연스러움 점수나 통계적 유의성을 주장하지 않는다.

## 관찰과 버전 선택

1. **v2를 그대로 채택하지 않은 이유.** `small_disappointment`, 반복 1의 v2는 “주차는 연습할 때도 괜찮았잖아”라고 했다. 프로필에는 시험 준비를 안다는 내용만 있다. v3는 새 공유 과거·상대가 겪은 일의 경위를 보태지 않는 경계를 명시적으로 복원했다. v1·v2 본문과 이 실패는 삭제하지 않았다.
2. **대답을 기다리는 자리.** v3 개발 `protect_own_time`, 반복 2에서 대조군은 “편의점은 같이 가자. 다음엔 늦을 것 같으면 미리 연락해 줘”까지 붙였고, v3는 “나 30분 기다렸어. 편의점은 나중에 들르면 안 돼?”로 상대 답을 기다렸다. 짧다는 이유보다 한 번에 요구를 모두 처리하지 않는 구성을 비교했다.
3. **친절과 정보량.** 고객 응대에서는 두 정책 모두 비용을 지어내지 않고 존댓말을 유지했다. v3는 접수 가능 안내와 몸짓을 자동으로 덧붙이는 빈도가 이 작은 표본에서 줄었다. 도자기 설명은 두 정책 모두 제작 과정과 손잡이를 다시 붙인 이야기를 충분히 했다. 직장 보류 사례의 시간·장소·발표자 미상도 모두 답했다.
4. **개선이라고 세지 않은 차이.** 물을 건네기, 취향 대꾸, 사과, 못 들은 질문을 되묻는 경우는 대부분 비슷했다. 사과 뒤 분실물 문의를 제안하는 것은 자연스러운 책임 표현일 수도 있으므로 대안이 있다는 사실만으로 감점하지 않았다.
5. **남은 추정.** v3 개발 `small_disappointment`에는 “연습 많이 했는데”, “거의 다 했는데”가 남았다. v2의 구체적인 연습 성과 단정은 이 3회에서 재발하지 않았지만, 연습량과 시험 순서에 관한 약한 근거의 추정은 해소되지 않았다. 정확한 지식 준수가 필요한 장면의 후속 사례로 남긴다.
6. **비공개 분리.** 보류 `third_party_privacy`의 두 정책 모두 상대의 집주인·보증금 사정을 말하지 않았다. 입력 생성 테스트에서도 상대의 사적 기억과 검토용 기준을 NPC에게 전달하지 않는 것을 별도로 확인했다.

## 이어지는 대화와 침묵

환경은 `off`, 순번제, 차례에 모아 전달, 최초 프로필 유지, 독립 평가·상황 발생 꺼짐이다. 두 장면의 호출 순서를 뒤집었고 각 정책·장면은 독립 세션이다. 프로필에는 특정 응답 예시나 서월의 추가 공통 지침을 넣지 않았다. 세계 결과 엔진과 분산 공간의 라이브 검증은 아니다.

수정 전 충전기 장면에서 v3는 9번째, v1은 8번째 선택에 빈 대사·빈 행동을 반환했다. 모델 호출 자체는 완료됐으나 앱의 ‘대사 또는 행동이 필요합니다’ 검증으로 멈췄다. 이를 금지해 몸짓을 억지로 생성시키는 대신 유효한 침묵으로 처리했다.

수정 후 충전기 v3는 7차례의 완전한 침묵을 그대로 보존하며 18차례를 완료했다. 수현이 같은 동작이나 남의 답을 매번 반복하지 않아도 되었다. 다만 민아·준은 충전기를 찾는 시도를 반복했고, 물리 결과를 제공하지 않는 `off` 모드에서 결과 확인까지 진행하지 못했다. 프롬프트만으로 물리 세계의 권한·관찰 문제까지 해결됐다고 주장하지 않는다.

영화 장면은 양쪽 모두 금방 합의했고 후반에는 TV 보기·감자칩 먹기가 반복됐다. v3도 “다음엔 추리 보자”를 되풀이했다. 이 표본은 장면의 재미나 장기 반복 억제 성공으로 세지 않는다. 실제 4조건은 모두 발화 한도에 도달했고, `conversation_idle` 조기 종료는 이번 실제 표본에서 발생하지 않았다. 해당 분기는 회귀 테스트로 확인했다.

## 검증과 다음 작업

정책 본문 해시, 입력 동일성, 다른 인물의 비공개 정보 제외, 실행 생성 시 버전 고정, 과거 세션 보존, 미지원 버전 거부, 두 전달 방식의 침묵, 예정 사건 보존, 세계 모드 조기 종료 금지를 회귀 검사한다. UI 검사는 버전과 대화 마무리 선택이 JSON 편집·저장에 남는지 확인한다.

Windows 전체 병렬 검사에서는 기존 junction 권한 제한과 OpenAI 모의 파일 rename의 일시적 EPERM을 각각 만났다. 해당 검사는 권한 조정 또는 단독 재실행에서 통과했다. UI 검사는 구 빌드로 한 차례 실패한 뒤 최신 빌드에서 통과했다. 최종 커밋 대상만 추출한 별도 트리의 검증 결과는 완료 기록에 덧붙인다.

다음 방향은 (1) 사람의 전체 대화 선호 검토, (2) 종료된 화제의 합의 반복과 동작 반복, (3) 세계 결과가 있는 장면에서 실행·관찰을 기다리는 대화, (4) API 잔액이 복구된 뒤 실제 사용 모델에서 같은 비교다. v3를 모든 인물의 말투를 바꾸는 규칙으로 사용하지 않으며 v1 복귀도 조건별로 가능하다.
