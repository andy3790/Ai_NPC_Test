# 기본 예제의 인물과 대화 안정화 · 2026-11-07

`harbor-profile/2`를 새 기본 예제에 채택한다. OpenAI 예제는 계정에서 사용할 수 있으면 NPC에 `gpt-6.1-sol/low`, 진행자와 평가자에 `gpt-6-luna/low`를 선택한다. 공통 NPC 정책은 **v5**, 서월 인물은 **원본 /1**을 유지한다. 언어 유지 문구를 추가한 `npc-dialogue/10`은 실제 연속 대화에서 실패하여 실험으로만 남긴다.

사용자는 인물 차이를 더 과장하기보다 제시한 연우·유진·하린 수준의 차이를 유지하며 전체 대화를 안정화하는 방향을 선택했다. 이번에는 그 인물들을 다시 쓰지 않고, 앱 기본 예제에서 확인한 반복 요약과 언어 이탈을 다뤘다.

## 원인과 변경

기존 윤의 프로필은 “상대의 말을 요약한 뒤 의견을 말한다”, 미루의 목표는 “둘이 합의할 수 있는 선택지를 정리한다”였다. 손잡이 만지기·팔짱 풀기 같은 동작도 매번 재현됐다. 공통 프롬프트만으로 줄이려던 해설과 중재를 개별 프로필이 다시 요구하고 있었다.

[프로필 버전](../../../src/shared/harbor-profiles.ts)의 /2는 성격·현재 목표·말투·예문·동작만 수정한다. 신분·관계·가치관·기억·지식·모르는 정보·금기와 세계·규칙 그래프는 보존한다. 윤은 직접 확인하고 점등하는 사람, 도하는 일을 맡아 움직이는 사람, 미루는 확인한 내용을 기록하려는 사람으로 썼다. 목표 문구도 수정했으므로 **말투만 바꾼 실험은 아니다**. 두 버전의 원문과 해시는 보존한다.

또한 `/api/example`이 카탈로그 첫 모델인 Luna를 선택해 `exampleSpec()`의 Sol 기본값을 덮어쓰고 있었다. 기본 예제의 대화 모델 선택을 별도로 정했다. Sol을 사용할 수 없으면 해당 계정의 기존 기본 모델로 돌아가며, Codex 모델 선택은 기존 방식이다. 저장된 설정과 실행의 모델·프로필은 변경하지 않는다. 새 예제의 발화 한도는 준비 중에 끝나던 6에서 18로 늘리고, 목표 달성 시 조기 종료와 동시 호출 1개는 유지한다. 실제 예제 검증에서 순번제가 질문받은 사람보다 다른 사람을 먼저 불러 같은 부탁이 반복돼, 새 예제는 검증된 진행자 v4를 사용하도록 선택했다. 모델·한도·진행 방식은 편집기에서 확인하고 바꿀 수 있다.

## 실행 증거

382회 비교 호출과 실제 앱 설정 검증 156회를 합쳐 **538회**, 로컬 가격표 기준 추정 **$0.79509306**, 사용량 미확인 0회다. 이는 이 보고서의 묶음이며 이전 단계 비용이나 계정 청구 총액이 아니다. [manifest](manifest.json)에 158개 증거 파일 해시·실험별 비용과 원본 위치, [판정 85쌍](judgments.json)에 A/B 매핑·근거 인용을 보존한다. 작성자가 후보와 매핑을 아는 **비독립 에이전트 검토**다. 사람 평가나 일반적인 품질 점수로 해석하지 않는다.

프로필 고정 입력은 3명 × 5상황이다. 공개 맥락·다른 인물의 프로필을 고정하고 이번 화자의 프로필만 바꾼다. 보류는 후보 /2를 동결한 뒤 실행했다. Luna의 같은 사례는 후속 모델 전이 검사로서 새로운 독립 보류 세트가 아니다. 기본 예제의 규칙 대화는 같은 규칙·세션 방식·진행자 v4를 사용했고 최대 18차례에서 목표를 달성하면 종료했다. 실제 9~10차례에 끝났으므로 장시간 세션을 검증했다는 뜻은 아니다.

언어 혼입 수는 대사와 행동의 일본어 문자 탐지 후 원문을 읽어 확인했다. 규칙 장면에는 인용해야 할 일본어 이름·작품명이 없었다. 전이 세트의 `となりのトトロ` 같은 작품명은 오류로 세지 않았다. 목표 완료는 규칙 진행 성공일 뿐 자연스러운 한국어 대화의 합격 판정이 아니다.

## 실제 출력과 채택 근거

- 기존 윤: “지금 할 수 있는 일부터 하자는 말씀이군요. 기름이 얼마나 남았는지부터 다시 확인하겠습니다.”
- 후보 윤: “먼저 불부터 켜 볼게요. 얼마나 쓰는지는 지켜봐야 해요.”
- 기존 윤의 동의: “오늘 밤 불빛을 우선하자는 말씀이군요. 저도 동의합니다.”
- 후보 윤의 동의: “저도 오늘 밤 쓰는 쪽이에요. 먼저 켜고 얼마나 줄어드는지 볼게요. 밤새 갈지는 아직 몰라요.”

첫 두 인용은 [Sol 개발 원문](sol-profile-development/samples.jsonl), 연속 대화 인용은 [기존 2회차](sol-v5/profile1-run2/transcript.md)와 [후보 2회차](sol-v5/profile2-run2/transcript.md)에서 확인할 수 있다. 손잡이를 잡는 행동 자체를 금지한 것은 아니다. 기름통을 실제 옮기려 잡는 것은 필요한 행동으로 남는다.

반면 미루의 후보 첫 대사는 아직 논의 중인데 어느 쪽으로 정했는지 묻는다. 윤은 차를 권해도 “저는 이제 불 켤 준비를 해야겠어요”로 돌아간다. 모든 인물이 모든 상황에서 개선된 것은 아니다. 평범한 차 거절이 서로 비슷한 것도 그 자체로 오류가 아니다.

Luna [후보 1회차](luna-v5/profile2-run1/transcript.md)에는 한국어 동의 뒤 일본어가 이어지고, 다음에는 대사와 동작이 모두 일본어로 바뀌었다. [v10 실패 원문](luna-v10/profile2-run1/transcript.md)도 보존한다. API 요청 원문을 확인하면 모든 후속 요청에 기존 한국어 시스템 지침이 전송된다. 지침 유실이나 UI 디코딩 오류로 돌리지 않는다. 단일 차례에서 성공한 v10을 채택하지 않은 이유다.

동일한 규칙 대화 4회에 Sol은 약 $0.1991, Luna는 약 $0.0174였다. Sol 기본 선택은 이 표본의 한국어·대화 품질을 우선한 결정이며 비용이 더 든다. 실제 청구·다른 장면의 비용이나 무오류 동작을 보장하지 않는다. 출력 후 번역·문장 절단이나 자동 재시도는 추가하지 않았다.

## 최종 앱 검증

`/api/example`이 돌려주는 설정을 그대로 받아 새 세션에서 실행했다. 평가도 켜고 두 전달 방식 모두 검사했다. [순번제 설정](app-round-robin/config.json)의 2회는 각각 12차례에 목표를 마쳤지만, 질문 당사자의 차례를 기다리는 동안 같은 점등 부탁이 반복됐다. 해당 실패 원문도 남긴다.

[최종 설정](app-final/config.json)은 Sol/low, 인물 /2, NPC v5, Luna 진행자 v4·평가자, 최대 18차례다. [모아서 전달](app-final/batch/transcript.md)과 [매번 전달](app-final/each/transcript.md) 모두 **9차례**에 각자의 동의·점등·기록을 끝냈고, 한국어 혼입이나 API 실패가 없었다. 미루의 점등 부탁 바로 뒤에 윤이 답하고 행동했다. 두 실행 합계 80회 API 호출, 약 **$0.14784**다. 한 번씩의 최종 검증이므로 성공률 추정이나 일반적인 속도·비용 개선 수치로 사용하지 않는다.

최종 코드의 타입 검사·빌드와 전체 **183/183 테스트**를 통과했다. 변경한 한도 18과 진행자 선택, Sol 사용 불가 시 대체 모델, 실제로 지원하는 effort, 저장된 설정 보존을 검사한다. 별도 모의 브라우저에서는 기본 v5·인물 /2와 실험 v10의 선택·실행·기록을 확인했고 화면 오류는 0이었다. 증거 파일 158개 해시, 고정 요청 170개 재구성, 연속 대화 호출 368개와 실제 전송 지침·입력·모델·effort, 인용 170개를 대조했다. 모의 검사와 언어 샘플의 결과를 인간 같은 반응의 보편적 보장으로 표시하지 않는다.

로컬 OpenAI 서버도 새 빌드로 갱신했다. 갱신 전 82개 실행은 모두 남았고, 이번 검토 16개가 조회 이력에 추가되어 98개가 됐다. 기존 일시정지 6개의 ID와 저장 설정 해시는 동일하며 실행 중 작업은 0개였다. 새 예제 API의 프로필 /2·Sol·진행자·18차례 설정을 실제 서버에서 다시 확인했다.

## 재현

```powershell
# 호출 없이 계획만 보려면 --live 제거
node --env-file-if-exists=.env --import tsx scripts/dialogue-eval.ts --cases evals/dialogue/harbor-profile1.json --candidate-cases evals/dialogue/harbor-profile2.json --baseline npc-dialogue/5 --candidate npc-dialogue/5 --split holdout --repetitions 2 --max-calls 36 --max-usd 1 --live
node --env-file-if-exists=.env --import tsx scripts/harbor-live.ts --model gpt-6.1-sol --policy npc-dialogue/5 --repetitions 2 --max-calls 140 --max-usd 1 --live
node --env-file-if-exists=.env --import tsx scripts/harbor-live.ts --model gpt-6-luna --policy npc-dialogue/10 --repetitions 2 --max-calls 140 --max-usd 1 --live
node --env-file-if-exists=.env --import tsx scripts/dialogue-eval.ts --cases evals/dialogue/language-recovery.json --baseline npc-dialogue/5 --candidate npc-dialogue/10 --model gpt-6-luna --split all --repetitions 2 --max-calls 24 --max-usd 1 --live
```

고정 입력 도구는 `--candidate-model`, `--candidate-effort`도 지원한다. 요청마다 실제 조건·모델·effort를 저장하며, 프로필 비교는 공개 정보나 다른 인물의 비공개 설정이 달라지면 실행 전에 거절한다. `max-usd`는 추정치 기반 다음 요청 차단선으로 마지막 한 요청은 넘을 수 있다. 자동 재요청은 하지 않는다.

다음 변경은 실제 출력에서 반복되거나 사용자 피드백으로 확인한 문제를 별도 회귀 사례로 만든 뒤 비교한다. 인물 차이를 강하게 만들기 위한 예문·성격 추가를 계속 쌓지 않는다. 이 버전에서는 서월 원본과 NPC v5·세계 v6·진행자 v4의 기존 채택 근거를 그대로 사용한다.
