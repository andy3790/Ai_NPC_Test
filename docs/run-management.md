# 기록 조회·설정 확인·삭제·백업

대화는 생성 즉시 SQLite에 저장합니다. 브라우저에서 별도로 저장하지 않아도 서버의 데이터가 남아 있으면 다시 볼 수 있습니다. 화면에 일부 기록만 보인다면 현재 저장소·실행 경로·필터·통합 검색 범위를 확인하세요.

## 여러 저장 위치를 한 화면에서 조회

기본 서버는 현재 DB와 통합 보관소를 함께 조회합니다.

| 구분 | 위치 / 역할 |
|---|---|
| Codex 기본 DB | `data/npc-lab.sqlite` |
| OpenAI 기본 DB | `data/openai/npc-lab.sqlite` |
| 사용자 지정 DB | `serve --data` 또는 `NPC_LAB_DATA` 폴더의 `npc-lab.sqlite` |
| 통합 보관소 | `data/history/npc-history.sqlite` |
| 기본 검색 루트 | 프로젝트의 `data/`, `reports/`, `.cache/` 및 현재 DB |
| 추가 검색 | `NPC_LAB_HISTORY_ROOTS`의 JSON 경로 배열 |
| 보관소 변경 | `NPC_LAB_HISTORY_DATABASE` |

```powershell
$env:NPC_LAB_HISTORY_ROOTS = '["D:/npc-runs","D:/npc-exports"]'
npm run start:openai
```

설정은 서버 시작 시 읽습니다. **기록 새로고침** 또는 `POST /api/history/refresh`로 외부 원본의 변경을 다시 가져옵니다. `GET /api/history`에서 검색 루트·원본별 loaded/unchanged/error·오류 사유를 볼 수 있습니다.

검색은 루트에서 깊이 5까지 `.sqlite`, `.sqlite3`, `.db`, `detail.json`, `records.jsonl`을 찾습니다. 심볼릭 링크와 runtime·sessions·history·node_modules·일부 임시 테스트 폴더 등은 제외합니다. CSV·Markdown·ZIP만으로는 자동 복원하지 않으므로 ZIP은 풀어 `records.jsonl`이 있는 폴더를 지정합니다. JSONL은 이 앱의 한 묶음 전체 내보내기 형식이어야 합니다.

같은 run ID는 하나로 표시합니다. 현재 DB → 외부 DB → detail.json → records.jsonl 순으로 선택하고, 같은 종류의 복사본은 최근 기록을 우선합니다. 같은 ID의 설정 해시가 다르면 충돌 오류를 남깁니다. 출처 경로는 모두 보존합니다.

현재 서버의 정지·완료 기록은 자동 보관됩니다. 외부 DB는 읽기 전용으로 열어 실행 상태를 바꾸지 않습니다. 원본이 사라져도 가져온 보관본은 자동 삭제하지 않습니다. 보관소의 고유 실행 수와 화면의 현재+보관 수는 다를 수 있습니다.

보관 기록은 조회·비교·내보내기가 가능하며, 재개·상황 투입·평가·검토 변경은 원본 DB를 연 서버에서 해야 합니다. `--no-history`는 통합 조회를 끄는 옵션입니다.

## 상세 필터와 비교

조건은 서로 AND로 적용하고 같은 필터의 여러 선택값은 OR입니다.

| 필터 | 기준 |
|---|---|
| 실행 경로 | 전체·실제 모델·Codex CLI·OpenAI API·모의 |
| 검색어 | 묶음/실험 ID·이름·시나리오·조건·NPC·모델·추론·출처 |
| 모델·추론 | **같은 NPC**가 두 조건을 함께 만족. 평가·진행자·엔진 모델은 제외 |
| 시나리오·상태 | 저장된 시나리오 ID, 실행 상태 |
| 전달·기억·진행·환경 | 실행 시 확정된 조건 |
| 저장 출처 | 현재 DB / 보관 기록 |
| 날짜·기간 | 생성 시각을 한국 시간 날짜로 판정. 시작일·종료일 포함 |
| 비용 범위 | USD 환산 합계. 계산 불가 기록은 범위 필터에서 제외 |
| 비용 계측 | 환산 가능·부분 계측·가정 포함·미계측. 가정 포함과 환산 가능은 겹칠 수 있음 |
| 발화·토큰·NPC 수 | 각각 NPC 선택 수·확인된 전체 토큰·참가자 수 |
| 응답 시간 범위 | 성공 호출의 중앙값, 화면 입력 단위 초 |

최소·최대는 경계를 포함하며 미확인 값은 0으로 취급하지 않습니다. 비용이 부분 합계이면 그 알려진 부분으로 범위를 판정하므로 비용 계측 필터도 함께 쓰세요. 날짜 필터는 완료 시각이 아닌 생성 시각입니다.

정렬은 최신/오래된 순, 비용·발화·토큰·응답 시간 순을 지원하며 미확인 값은 뒤에 둡니다. 상단 합계와 카드의 환산 비용도 현재 필터 결과 기준입니다. 모델·환경·시나리오·길이가 다른 기록을 섞은 합계는 동일 조건 성능 비교와 구분하세요. 지표별 분모는 [데이터와 평가](data-and-evaluation.md)에 있습니다.

## 해당 테스트의 설정 확인

묶음을 열어 **실행 설정**에서 실험·조건·반복, 원본 세계관·시작 상황, 캐릭터 프로필, 최종 NPC 모델·추론, 평가·진행자·세계·상황 엔진, 장소·통로·채널·시작 위치, 예약 사건, 버전·해시를 확인합니다.

`run.spec`는 원본 실험, `run.variant`는 해당 조건입니다. `scenario.defaults`가 곧 모든 NPC의 최종 모델은 아니므로 적용된 세션 설정도 함께 봅니다. 편집 화면에서 이후 변경한 설정은 과거 기록에 반영되지 않습니다. 오래된 기록에서 버전·실제 모델이 없으면 현재 값으로 추정해 채우지 않습니다.

설정 다운로드는 스냅샷 래퍼입니다. 새 실험에 재사용하려면 내부 `spec`을 꺼내고 조건·반복 수를 조정합니다. 원본 스냅샷을 수정해서 기존 실행 결과를 바꾸지는 않습니다.

## 삭제와 일괄 선택

1. 카드의 삭제 또는 체크박스로 여러 묶음을 선택합니다. **필터 결과 전체 선택**은 현재 필터에 맞는 ID를 선택합니다.
2. 선택을 검토하고 삭제 미리보기를 엽니다. 선택 개수·삭제 가능 개수·막힌 이유·원본/보관/파일 범위를 확인합니다.
3. 최종 확인 후 실제 삭제합니다. 일부 실패하면 성공한 삭제는 유지하고 실패한 ID를 표시합니다.

필터 전체 선택은 이후 새로 생긴 기록을 계속 자동 선택하는 규칙이 아닙니다. 삭제 확인에 표시된 ID·개수를 기준으로 검토하세요. 실행 중 또는 요청을 처리 중인 묶음은 바로 삭제할 수 없으며 먼저 일시정지·중단 처리가 끝나야 합니다. 확인 중 대상이 바뀌면 새 확인이 필요합니다.

삭제 대상은 현재·발견된 원본 DB의 해당 실행 행, 통합 보관본, 앱이 식별한 해당 실행의 내보내기·보조 파일입니다. 같은 DB의 다른 묶음과 DB 파일 전체를 지우지 않습니다. 외부 원본 서버가 사용 중이면 차단합니다. 여러 DB·파일을 아우르는 완전한 원자적 삭제는 아니므로 일부 실패 시 새 미리보기를 받고 남은 대상만 재시도합니다.

브라우저에서 내려받은 ZIP, 검색 범위 밖의 복사본·백업, Codex의 전역 기록, OpenAI 원격 response는 이 삭제로 제거되지 않습니다. 삭제한 실행을 포함한 외부 백업을 나중에 검색 루트에 넣으면 다시 가져올 수 있습니다. 확인 토큰은 [API 문서](api.md)의 삭제 흐름을 따릅니다.

## 백업과 이전

조회용 분석 자료와 실행 재개용 백업은 다릅니다.

- **조회·분석 보관:** 묶음별 ZIP을 내보냅니다. `records.jsonl`은 원본 기록·이벤트, `config.json`은 설정 스냅샷입니다. CSV·Markdown은 분석·읽기용입니다.
- **서버 이전·복구:** 실험을 안정된 경계에서 일시정지하고 서버를 정상 종료한 뒤 해당 데이터 폴더 전체와 통합 보관소를 복사합니다. API의 `runtime/openai` 세션·호출 파일 등도 필요합니다.
- **외부 모델 세션:** Codex thread나 저장된 API response의 접근 가능성은 로컬 DB 복사만으로 보장되지 않습니다. 원본 계정·CLI 상태·서버 측 보존 조건도 영향을 줍니다.

실행 중 SQLite는 WAL 파일에 최신 데이터가 있을 수 있으므로 `.sqlite`만 임의 복사하지 마세요. 정상 종료 후 복사하거나 SQLite에 맞는 백업 절차를 사용합니다. 테스트·분석 원본을 공개할 때는 비공개 프로필·귓속말·경로가 포함된다는 점을 [보안 문서](../SECURITY.md)에서 확인하세요.
