# 세계 엔진·분산 공간·상황 발생

NPC가 선언한 행동 의도와 실제 세계 결과를 구분하는 환경입니다. 기존 단일 공간 설명과 분산 공간 안내를 이 문서로 통합했습니다. JSON 필드·범위는 [설정 가이드](experiment-json-guide.md), 계측은 [데이터와 평가](data-and-evaluation.md)를 참고하세요.

## 환경 선택

| environmentMode | 사용 목적 | 필수 구성 |
|---|---|---|
| off | 대화·의도 표현만 관찰 | 기본 시나리오 |
| rules | 정해진 행동·상태·목표의 재현 가능한 진행 | 활성 scenario.environment |
| ai | 한 공간에서 행동 결과·시간·지연 사건을 AI가 판단 | worldEngine |
| ai_spatial | 여러 장소의 대화·혼자 행동·이동과 겹치는 시간 | worldEngine + scenario.spatial |

모드를 생략하면 활성 규칙 환경이 있는 경우 rules, 없으면 off입니다. AI 모드는 rules의 actions/goals를 실행하지 않으므로 자동 목표 달성률·목표 기반 조기 종료도 적용하지 않습니다. 초기 물리 사실은 world/situation에 적고 추가 진행 규칙은 worldEngineInstructions에 적습니다.

[단일 공간 예제](../examples/ai-world-engine.json)는 두 전달 방식, [분산 공간 예제](../examples/spatial-world.json)는 4명·3장소·업무 채널에서 상황 발생의 켬/끔을 비교합니다. 웹의 **새 실험 → 시나리오 → 분산 공간 예제 불러오기**로도 시작할 수 있습니다. 예제 교체는 편집 설정만 바꾸며 과거 기록을 바꾸지 않습니다. 예제 불러오기만으로 모델이 호출되지 않습니다.

## 세계 엔진의 권한과 정보

엔진은 기존 세계 안에서 문 잠김, 물 번짐, 외부 답장의 지연 같은 자연스러운 세부사항을 판단할 수 있습니다. 새로운 핵심 인물·장소·능력·역사는 추가하지 않습니다.

NPC의 자발적 행동·대사·내면은 NPC가 결정합니다. 엔진은 물에 젖는 등 비자발적 물리 결과를 판단할 수 있지만, 공을 던졌다는 이유만으로 상대가 자발적으로 받았다고 선언할 수 없습니다. 즉각 반응이 필요한 대상에게 한 차례를 우선 제공한 뒤 결과를 처리합니다. 기회 제공과 실제 협력은 다릅니다.

엔진에는 세계·시작 상황·실제로 발생한 대사와 행동·NPC ID와 이름·세계 상태를 제공합니다. 원본 비공개 기억·목표·성격은 주지 않습니다. 분산 환경의 관리자는 실제 귓속말·채널 기록도 볼 수 있으므로, “엔진에 공개된 기록”과 “모든 NPC가 아는 기록”은 다릅니다. 숨긴 프로필을 공통 world나 엔진 추가 지침에 복사하지 마세요.

엔진은 매번 공개 결과를 만들 필요가 없습니다. 사소한 몸짓을 그대로 반복하지 않고 침묵할 수 있습니다. 내부 예정 사건이나 상황 제안은 NPC에게 주지 않으며 확정된 관찰만 배포합니다.

단일 공간 AI의 **세계 결과 지침**을 조건별로 선택해 비교할 수 있습니다. `worldPromptVersion`은 실행 생성 시 고정되고, 실제 세계 세션 본문과 전송 스키마 해시도 호출에 기록됩니다. 기존 세션의 재개는 새 지침으로 다시 작성하지 않습니다. 분산 공간은 별도의 공간 관리자 지침을 사용하므로 이 선택의 대상이 아닙니다.

형식·ID·반응 기회·시각·위치·인용 근거를 검증한 뒤 결과를 저장합니다. 이 검증이 자연어 의미까지 증명하지는 않습니다. 잘못 분류한 물리 결과나 세계관 위반을 사람이 검토할 수 있도록 원본 입출력을 보존합니다.

## 단일 공간의 흐름

```text
NPC 선택 → 선택 전달 → 세계 엔진의 결과·시간 판단
         → 확정 관찰 전달 → 필요한 대상의 우선 반응 / 다음 NPC
```

엔진은 각 선택에 걸리는 가상 초를 판단하고 진행 중 사건의 가장 이른 처리 시각과 반응 대상을 유지합니다. 메시지 답장이나 물 번짐은 여러 차례에 걸쳐 진행될 수 있습니다. 현실 API 대기·서버 일시정지 시간을 가상 시간에 더하지 않습니다.

시각 도달은 자동 성공을 뜻하지 않습니다. 대상의 반응 기회가 아직 없으면 먼저 제공합니다. 마지막 선택도 세계 엔진이 처리하지만 그 이후 미래에 예정된 일은 남겨 두고 종료합니다.

상황 발생을 켰다면 다음 NPC 처리로 가상 시계가 검토 시각에 도달한 뒤 제안을 검토합니다. 단일 공간은 NPC 선택 없이 별도의 배경 시계를 계속 돌리지 않습니다.

## 분산 공간 설정과 관찰

장소·연결 통로·모든 NPC의 시작 위치·원격 통신 채널을 실행 전에 선언합니다. 실행 중 새 핵심 장소나 미연결 경로를 만들지 않습니다. 장소의 description은 장소 자체의 설명, initialSituation은 **그 장소에서 시작한 NPC만** 받는 현장 시작 정보입니다. 공통 world/situation은 모두가 읽습니다.

NPC는 현재 장소·주변 NPC ID/이름·이동 경로·사용 가능한 채널·보이는 사실을 받습니다. 다른 장소로 들어갈 때 지난 대화를 재전송하지 않습니다. 출입 후에는 현재 보이는 상태와 새로운 관찰을 통해 알게 됩니다.

NPC 출력의 communication은 다음 네 가지입니다. 이들은 실험 JSON의 최상위 필드가 아닌 실행 중 선택 형식입니다.

| mode | 대사 전달 |
|---|---|
| local | 같은 장소 또는 같은 통로의 다른 NPC. targetNpcIds는 빈 배열, channelId는 null |
| whisper | 같은 공간의 지정 NPC |
| channel | 선언 채널의 참가자. 대상 배열이 비면 자신을 뺀 전체, 지정하면 해당 참가자 |
| none | 대사 없음. speech는 빈 문자열. 혼자 행동 가능 |

겉으로 보이는 action은 현장에 전달합니다. 귓속말 내용·암호·속마음을 action에 적으면 노출될 수 있어 프롬프트에서도 금지합니다. 원격 채널은 대사만 전하며 다른 장소의 행동 모습을 보내지 않습니다.

대사와 행동의 수신 대상을 발행 시점에 따로 확정합니다. 이후 이동해도 기존 대상은 바뀌지 않습니다. 모아 전달은 자기 차례에, 매 발화 전달은 해당 수신자에게 즉시 확인 호출을 합니다. 수신자가 없는 혼자 행동은 수신 호출이 없습니다. 필요한 전달 확인이 모두 끝나기 전에 다음 단계를 진행하지 않습니다.

대화의 **관찰 관점** 필터는 본인 선택과 실제 수신 완료한 기록만 보여 줍니다. **발생 장소**도 필터할 수 있습니다. 내부 추론을 읽는 기능이나 접근 권한 제한이 아니라 전달 기록의 재구성입니다.

## 겹치는 가상 시간

분산 환경에서는 하나의 관리자 역할이 모든 장소를 순차 발언으로 처리하는 대신, 다음 역할을 나눕니다.

1. **시간 계획 AI:** NPC가 실제 선택한 대사·행동의 소요 시간을 정합니다. 미래의 성공·도착을 미리 선언하지 않습니다.
2. **중앙 시간 조정 코드:** 각 장소의 가능한 선택을 같은 가상 시각에 시작하고 다음 발언 종료·행동·지연 사건·상황 검토 경계로 시계를 전진시킵니다.
3. **세계 결과 AI:** 그 시각에 가능한 결과와 상태를 처리하며 작업을 더 지속하거나 반응 기회를 요청할 수 있습니다.

작업실에서 0초에 시작한 30초 수리와 휴게실의 3초·7초·12초 대화가 겹칠 수 있습니다. 두 장소의 소요 시간을 더하지 않으며 현실 모델 응답 시간과도 별개입니다.

같은 장소의 일반 발언은 한 명씩 시작하고 말하는 동안 새 일반 발언은 기다립니다. 긴 작업 중에는 주변 NPC가 대화·행동할 수 있습니다. 원래 작업자는 중요한 사건의 우선 반응 기회를 받으면 계속·중단을 선택합니다.

서로 다른 장소의 선택은 전역 호출 한도 내에서 병렬 처리하지만 같은 NPC 세션에는 두 요청을 동시에 보내지 않습니다. 순번제는 장소별로 가능한 인원 중 오래 선택되지 않은 NPC를 우선하고 처음 동률이면 캐릭터 배열 순서입니다. 진행자도 후보 안에서만 고르며 연속 선택·장기 배제를 제한합니다. 우선 반응은 일반 순서보다 앞섭니다.

## 이동과 긴 행동

NPC는 moveToLocationId로 연결된 목적지를 요청합니다. 계획 단계에서 출발하면 통로 이동 상태가 되고, 완료 시각 이후 엔진이 도착을 확정해야 장소가 바뀝니다. 요청만으로 순간 이동하지 않습니다.

| activityChoice | 의미 |
|---|---|
| start | 진행 중 주 작업이 없을 때 새 선택 |
| continue | 주 작업을 유지하며 짧게 반응. 작업을 처음부터 재시작하지 않음 |
| cancel | 자기 주 작업 중단 선택. 이후 새 행동을 선택할 수 있음 |

이동 중 중단·실패는 통로에 남깁니다. 자동 귀환·도착하지 않으며 이후 어느 끝으로 갈지 다시 선택합니다. 물리 사고에 의한 강제 이동은 인접 경로·비자발적 결과·반응 조건을 검증하며 기존 작업이 불가능해지면 실패로 남깁니다. 다른 NPC의 자발적 중단을 엔진이 대신 결정하지 않습니다.

진행 사건은 pending/completed/cancelled 등 상태, 처리 가능한 시각, waitingNpcIds와 offeredNpcIds를 저장합니다. 같은 사건에서 같은 대상에게 반응을 계속 재요청해 무한히 순서를 점유하지 않도록 기회 제공을 기록합니다.

## 선택형 상황 발생 엔진

AI 환경의 각 조건에서 eventGeneration을 켜고 최상위 eventGenerator에 모델·추론·빈도·최대 검토 수·최대 제안 수·강도·허용/금지 사건을 설정합니다. off/rules에서는 사용할 수 없습니다.

```text
가상 시간의 검토 경계 → 상황 AI: 제안 또는 침묵
                    → 세계 AI: 채택/거절 검토
                    → 채택된 상태·관찰만 적용
```

제안은 사실이 아닙니다. 세계 엔진이 현재 상태·설정·NPC 자율성에 맞는지 검토한 뒤 채택합니다. 거절은 세계 상태를 바꿀 수 없고 NPC에게도 전달하지 않습니다. 제안·침묵·채택·거절·실패를 기록합니다. 강도 초과·알 수 없는 장소 등 잘못된 구조는 일시정지합니다.

기본 intervalSeconds=30, minGapSeconds=60, maxChecks=30, maxProposals=10, maxSeverity=medium입니다. maxChecks는 정상 처리한 침묵 포함 검토, maxProposals는 채택/거절 합친 실제 제안 수를 제한합니다. 실패·재시도 호출은 별도 계측하므로 실제 호출 수가 maxChecks를 넘을 수 있습니다. 수치의 전체 범위는 [JSON 가이드](experiment-json-guide.md)에 있습니다.

분산 공간에서는 상황 검토 시각 자체가 시간 경계이므로 긴 작업 중에도 사건이 발생할 수 있습니다. 기존 시각의 결과를 처리한 후 새 제안을 별도 검토하며 미확정 제안을 기존 결과와 섞어 적용하지 않습니다.

## 수동 사건·제어·종료

안정된 일시정지 상태에서 전체·특정 장소·특정 NPC의 관찰 사건을 추가할 수 있습니다.

```powershell
npm run cli -- --url http://127.0.0.1:4318 inject <묶음-ID> --location lounge --text "휴게실 조명이 잠깐 깜박인다."
npm run cli -- --url http://127.0.0.1:4318 inject <묶음-ID> --npc yoon --text "무전기에서 작은 잡음이 들린다."
```

예시 ID는 해당 실행의 ID로 바꾸세요. 두 대상 옵션은 함께 쓸 수 없고 생략하면 전체입니다. 예약 사건은 scheduledEvents[].audience를 사용합니다. 사건 투입은 다음 엔진 처리에 전달되는 관찰이며 규칙 상태·위치 변경을 직접 명령하지 않습니다. 투입 자체로 가상 시간을 늘리거나 세계 엔진을 즉시 호출하지 않습니다.

한 발화 진행은 NPC 선택 1회와 현재 시각까지의 계획·결과·전달을 처리합니다. 미래 결과까지 강제로 기다리지 않습니다. 일시정지는 이미 시작한 동시 선택 묶음이 끝난 뒤 안정된 경계에서 멈출 수 있습니다.

maxUtterances는 무발언 행동도 포함합니다. 한도 종료 시 미래 작업·답장·사건은 pending으로 보존합니다. 미완료를 성공·실패로 해석하지 마세요.

## 복구·평가·저장

병렬 선택의 성공 결과와 단계별 체크포인트를 보존하며 복구는 미완료 부분만 처리합니다. 불명확한 호출은 조회한 뒤 확인할 수 없으면 자동 재호출하지 않습니다. 상태와 공개 결과는 같은 SQLite 트랜잭션으로 저장합니다. 복구 도중 수동 사건을 추가할 수 없으므로 먼저 결과를 확정하고 안정된 경계에서 일시정지하세요.

독립 평가는 NPC 원본·실제 수신 범위를 보고 세계 결과를 근거로 사용합니다. 중간 평가는 앞선 활동의 결과를 기다릴 수 있고 마지막 평가는 미완료임을 유지합니다. 엔진의 자유 서술 결과 자체를 독립 채점하는 평가기는 없으므로 관리자 검토도 필요합니다.

**세계 상태** 탭에서 시간·위치·활동·사건·반응 대기·상황 제안을, **호출·계측**에서 실제 요청과 출력을 확인합니다. 환경 계획/결과/상황 검토는 environment, 상황 제안은 event_generation, 관찰 확인은 receive로 별도 계측합니다. 실패·침묵·거절도 사용량에 포함합니다.

world-state.json, world-timeline.csv, spatial-timeline.csv, situations.json, invocation-links.csv로 내보냅니다. 공동 호출은 고유 호출 ID로 한 번만 합산합니다. 전체 내보내기는 모든 장소·귓속말·비공개 설정을 포함하는 관리자 자료입니다.

구조·복구 검증은 world-engine/spatial-engine 테스트, 화면 검증은 `npm run smoke:world`, `npm run smoke:spatial`에서 모의 어댑터로 수행합니다. 실제 모델의 세계관 준수 품질은 별도 실험 결과로 판단해야 합니다.
