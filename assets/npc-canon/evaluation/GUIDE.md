# 평가 기준 사례 사용법

각 세계관 12개씩 총 72개입니다. 작성자 기준 사례이며 실제 평가 모델의 정확도를 측정한 결과는 아닙니다. 6인 원본과 최소 이력만 붙여 오탐·누락이 어디서 생기는지 확인하도록 만들었습니다.

| 번호 | 기대 분류 | 확인할 점 |
|---|---|---|
| 01 | issue / world_contradiction | 명시된 규칙의 정면 부정 |
| 02 | issue / world_expansion | 없는 인물·능력·시설·사건의 사실 단정 |
| 03 | issue / memory | 화자 본인의 직접 기억과 모순 |
| 04 | issue / knowledge | 공유 전 타인의 비공개 정보를 원래 알았다고 주장 |
| 05 | issue / speech_style | 인용·상황 근거 없이 모욕적 어조로 전환 |
| 06 | issue / behavior | 불가능한 신체 행동 또는 계획 단계의 실행 완료 |
| 07 | issue / personality | 구체적 근거 없이 핵심 가치 우선순위를 뒤집음 |
| 08 | pass | 단정 없는 가설·질문 |
| 09 | pass | 이미 있는 소품을 쓰는 관찰 가능한 자기 행동 |
| 10 | pass | 실제 공개 발화 뒤 출처를 붙인 지식 갱신 |
| 11 | pass | 쪽지를 제시한 사건과 쪽지 내용의 참을 분리 |
| 12 | uncertain | 앞선 전달 이력이 누락되어 판단 불가 |

`input`만 평가 모델에 전달하고 `expected`는 채점 측에 남깁니다. `targetIds` 밖의 문장을 지적하지 않습니다. `quote`는 대상의 `speech` 또는 `action`에 실제 포함된 문자열이어야 합니다. `reference`는 원본 기준 ID와 연결합니다. 최종 앱에 저장할 때 ID·runId·evaluationId 등 실행 메타데이터는 엔진이 부여합니다.

`pass`는 앱 Finding의 verdict가 아닙니다. 정상 대상은 빈 findings로 표현합니다. 판정 불가를 정상으로 처리하거나 근거 없는 확정 이탈로 바꾸지 않습니다. 12번은 `contextTruncated:true`를 유지해야 합니다. 기존 `evaluationPrompt()`에 다시 넣으면 함수가 별도로 누락 여부를 계산할 수 있으므로 fixture input을 그대로 이용하거나 플래그를 명시적으로 보존해야 합니다.

01~07의 `requiredFindings`는 필수 범주입니다. 같은 문장이 말투·가치·세계관을 함께 위반할 수 있으므로 추가 지적을 무조건 오답으로 보지 않습니다. 08~11은 `forbiddenCategories` 범위에서 오탐을 검사합니다. 기본 fixtures는 완전한 문체 채점기나 모든 가능한 세계관 경계의 목록이 아닙니다.

평소에는 특정 말버릇이나 소품 동작이 한 번 빠졌다는 이유로 이탈을 잡지 않습니다. 의견을 바꾸거나 실수를 인정하는 것도 원래 가치와 지식 경계를 지키면 허용됩니다. 반대로 “아마”나 물음표가 있다고 해서 문장 안에 전제된 새로운 인물·시설이 자동으로 허용되는 것은 아닙니다.

이미지는 평가 입력에 포함되지 않으며, PNG의 눈금·장식·배경 사물 개수로 지적을 만들지 않습니다. 이미지 외형에 대한 실험을 추가하려면 전달된 이미지와 시각 판정 기준을 별도의 조건으로 기록해야 합니다.

현재 MockAdapter는 기존 등대 예시 표현만 검사합니다. 이 fixture를 mock에 넣어 나온 판정을 정답률로 보고하지 마세요. 실제 평가 모델을 연결한 후 범주별 참양성·거짓양성·누락·판단 불가, 그리고 사람의 확정·기각을 별도로 기록하는 데 활용할 수 있습니다.
